## 1. Вердикт

Проект — качественный **прототип-витрина**, но **не рабочий сайт клуба**. Каркас, дизайн-система и вёрстка сделаны на хорошем уровне; ТЗ выполнено на ~75% по объёму и на ~40% по сути, потому что провалены два ключевых требования:

1. **Этап 11 (GraphQL) не выполнен** — `USE_MOCKS_ONLY = true`, ни один байт данных не приходит с бэкенда. Главная страница вообще не подключена к слою данных: цифры, тренеры, турнирная таблица, отзывы захардкожены прямо в `.vue`-компонентах.
2. **Основной бизнес-сценарий сломан** — кнопка «Записаться» в шапке и в hero не делает ничего, а обе формы заявки на живом сайте показывают «Заявка отправлена», никуда её не отправляя.

Сайт **опубликован в интернете** (`flowise.dinamchiki.ru`, HTTP 200, Caddy), открыт для индексации, с плейсхолдерными телефонами и неработающими формами. Это не «незаконченный этап», это публичная витрина, вводящая посетителя в заблуждение.

**Техническое качество того, что сделано:** высокое. `vue-tsc --noEmit` — 0 ошибок, `vite build` проходит за 7 с, 0 ошибок в консоли на всех 8 маршрутах, 0 горизонтальных переполнений на 390 px, 12 348 строк в 104 файлах, JS ~148 KB gzip.

**Починка:** `<BaseButton to="/contacts#lead">` — одна строка на каждую кнопку.

### К-2. Формы заявки имитируют отправку

- `src/widgets/home/HomeCta.vue:26-31` — `onSubmit()` ставит `submitted = true`, ждёт 3.5 с, очищает поля. Ни валидации, ни сети, ни логирования. Пользователь видит благодарность, заявка исчезает.
- `src/widgets/contact/LeadForm.vue` → `useSubmitApplicationMutation()` → `composables.ts:306` — при `USE_MOCKS_ONLY = true` возвращает `{ ok: true, leadId: 'lead-<timestamp>' }` после `setTimeout(800)`. Пользователь получает «Номер заявки: lead-mf3x9k» — несуществующий идентификатор.

Это работает **на живом публичном домене**. Родитель, оставивший заявку, будет ждать звонка, которого не будет.

**Починка (минимум):** до появления бэкенда убрать success-состояние и заменить его на прямые контакты (телефон/Telegram/WhatsApp), либо повесить форму на реальный приёмник (Telegram Bot API — в соседних проектах `squad-bot`/`bestplayer-bot` инфраструктура уже есть).

### К-3. Этап 11 не выполнен: данных из GraphQL нет

- `src/shared/api/config.ts:14` — `export const USE_MOCKS_ONLY = true`.
- `curl https://apigql.dinamchiki.ru/query` → **HTTP 000**, соединение не устанавливается. Бэкенда физически нет.
- Схема спроектирована (`graphql/queries.ts`, 351 строка, 12 фрагментов, 17 запросов + мутация) и это сделано грамотно — но не проверена ни одним реальным ответом.
- Требование ТЗ «REST не использовать» формально соблюдено (REST-вызовов нет), фактически нарушено — нет вообще никаких вызовов.

### К-4. Главная страница не подключена к слою данных вообще

`HomePage.vue` не импортирует ни одного composable. Данные лежат литералами внутри виджетов:

| `HomeCoachesPreview.vue` | 23 | список тренеров |
| `HomeTournamentsPreview.vue` | 45, 53 | турнирная таблица и результаты матчей |
| `HomeGalleryPreview.vue` | 22 | отзывы родителей |

| `HomeWhyUs.vue` | 16 | преимущества |

Переключение `USE_MOCKS_ONLY = false` **не оживит главную** — её придётся переписывать отдельно. README утверждает обратное: «Никаких изменений в страницах/виджетах не требуется». Это неверно для главной.

### К-5. Страница игрока недостижима из интерфейса

`/player/:id` работает только по прямому вводу URL. Причина: у команды нет состава — `team.types.ts:39` содержит только `playersCount: number`, массива игроков нет. `TeamDetailPage.vue` не выводит ни одной ссылки на игрока, `TournamentDetailPage.vue` — тоже (только карточки команд, строки 155–175).

Следствие: этап 8 сделан впустую, `PlayerCard.vue` не используется нигде.

## 5. Существенные находки

### С-1. Пункт меню «Новости» ведёт в галерею

`AppHeader.vue:32` — `{ to: '/gallery', label: 'Новости' }`. Пользователь кликает «Новости», попадает на страницу с `<h1>Моменты из жизни клуба</h1>` и сеткой фото. Раздела новостей в ТЗ нет, но и подменять его галереей нельзя — либо переименовать пункт в «Галерея», либо завести `/news`.

Там же `AppHeader.vue:30` — `/coaches` подписан «Тренеры», хотя в мокапе на этой позиции «Тренировки». Расхождение с мокапом сознательное и корректное (роут `/coaches`), но зафиксировать стоит.

### С-2. Три разных телефона клуба

| Место | Номер |
|---|---|
| `AppHeader.vue:45` | `+7 (495) 123-45-67` — московский код, взят из мокапа |
| `contacts.mocks.ts:9` | `+7 (8652) 00-00-00` — ставропольский код, но нулевой номер |
| `index.html:72` (JSON-LD) | `+7-8652-000-000` |

В шапке на каждой странице висит `tel:+74951234567` — кликабельный звонок в никуда. JSON-LD с фиктивным телефоном отдаётся поисковикам как структурированные данные организации.

### С-3. Прод отдаёт HTTP 200 на несуществующие страницы

`https://flowise.dinamchiki.ru/nope` → **HTTP 200** + страница «Страница не найдена». Классический soft-404: поисковик индексирует мусорные URL. `noindex` в meta выставляется (`router/index.ts`, `meta.noIndex`), но только после исполнения JS — краулер видит 200.

### С-4. Staging открыт для индексации и указывает на чужой домен

- `public/robots.txt` — `Allow: /` без ограничений, сайт живёт на `flowise.dinamchiki.ru`.
- `Sitemap: https://dynamost.ru/sitemap.xml` — ссылка на другой домен.
- `public/sitemap.xml` — все `<loc>` указывают на `https://dynamost.ru/...`.
- `index.html:44` — `<link rel="canonical" href="https://dynamost.ru/">`.

Итог: тестовый стенд с фиктивными телефонами открыт всем краулерам и при этом «отдаёт вес» домену, на котором его содержимого нет. Для стенда нужен `Disallow: /` либо HTTP-заголовок `X-Robots-Tag: noindex`.

### С-5. Расхождение фактического деплоя с описанным

- Живой сервер отвечает `server: Caddy`, `/healthz` → **200 с телом `index.html`** (SPA-fallback), то есть `docker/nginx.conf` с его `location = /healthz { return 200 "ok" }` **на проде не используется**.
- `scripts/deploy.sh:118` в финале печатает «Не забудь добавить vhost в nginx (**на проде Caddy нет**)» — прямо противоречит заголовкам живого сервера.
- `docker-compose.yml` + `Dockerfile` + `docker/nginx.conf` — работающая, но не задействованная ветка деплоя.
- README описывает третий вариант — Caddy на `dynamost.ru` с проксированием `/graphql`.

Три несогласованных описания деплоя при одном фактическом. Хэши ассетов live совпадают с локальным `dist/` — то есть задеплоена актуальная сборка, но каким именно путём, из документации не следует.

### С-6. Мёртвый дублирующий слой доступа к данным

`src/shared/api/{teams,coaches,tournaments,players,gallery}.ts` — 139 строк функций `fetchTeams()`, `fetchCoach()` и т.д. Полностью вытеснены `composables.ts`, **не импортируются нигде**. Из `contacts.ts` (46 строк) используется только `validateLeadForm`. `src/shared/api/index.ts` с `HEALTH_QUERY`/`useHealth()` не используется вовсе.

Также не используются:
- `src/widgets/player/PlayerCard.vue` (136 строк)
- `src/shared/ui/base/ContentPlaceholder.vue`
- `GRAPHQL_TIMEOUT_MS` (`config.ts:17`) — объявлен, нигде не читается

Итого ~350 строк мёртвого кода.

### С-7. `useMutation` вызывается вне setup-контекста

`composables.ts:316` — `const { mutate } = useMutation(...)` внутри `async function submit()`, после `await`. Composable Vue Apollo вызывается вне жизненного цикла компонента, при каждой отправке формы создаётся новый экземпляр мутации. Сейчас ветка недостижима (`USE_MOCKS_ONLY = true`), но сработает сразу после переключения флага. Правильно — поднять `useMutation` на уровень `useSubmitApplicationMutation()`.

### С-8. Заявленный focus-trap не реализован

`LightboxModal.vue:10` — комментарий «Focus-trap (Escape + Tab)». Фактически обрабатываются только `Escape` и стрелки; Tab не перехватывается, фокус уходит на элементы под модалкой. `aria-modal="true"` и `role="dialog"` выставлены — то есть заявка на доступность есть, реализация не доведена.

### С-9. Комментарий из чужого проекта в продакшн-коде

`src/app/providers/apollo.ts:21-23`:
```ts
fetchOptions: {
  // 15 секунд — иначе бот Юрия бесится при висящем бэке
  // см. user-profile memory: «curl/requests ВСЕГДА с таймаутом»
},
```
Объект пустой — таймаут **не выставлен**. Комментарий описывает несуществующее поведение и ссылается на посторонний контекст. При недоступном бэкенде (текущее состояние!) запрос будет висеть до дефолтного таймаута браузера.

## 6. Полировка (этап 12 не завершён)

**Обнаружено на скриншотах прода:**

- **`StatCard`** — flex «иконка слева / текст справа»: при 4 карточках в ряд на 1280 px под текст остаётся ~170 px. Подписи ломаются в узкую колонку («Мальчиков и / девочек / тренируются в / клубе»), карточка выглядит полупустой справа. В мокапе 3 цифра и подпись занимают всю ширину.
- **Карточки возрастных групп** — картинка-плейсхолдер съедает ~45% ширины, заголовок «Младшая группа» переносится на две строки, кнопки «Подробнее» стоят на разной высоте в соседних карточках (нет `margin-top: auto`).
- **Hero на мобиле** — бейдж «10+ лет опыта» выходит за левую границу карточки-визуала.
- **Логотип** — `LogoMark.vue` рисует простой щит с «Д». В мокапе — монограмма «Динамо» с двумя звёздами и мячом. Узнаваемость бренда потеряна.
- **Ни одного `<img>` во всём проекте.** Все фото (hero, тренеры, игроки, команды, галерея, карта) — декоративные SVG-заглушки. Визуально аккуратно, но сайт детского клуба без единой фотографии детей не решает свою задачу.

**Что с адаптивом хорошо:** 33 медиазапроса по трём брейкпоинтам, `StandingsTable` получает `overflow-x: auto` + `-webkit-overflow-scrolling: touch`, проверено — на 390 px горизонтального скролла страницы нет ни на одном маршруте.

## 8. Что сделано хорошо

Чтобы оценка была честной:

- **Архитектура.** Чистый FSD: `app / pages / widgets / entities / shared`. Границы слоёв не нарушены, циклических импортов нет.
- **Дизайн-токены.** `variables.scss` — полноценная система: 10 оттенков бренда, семантические алиасы, шкала отступов 4 px, типографическая шкала, 4 уровня теней, 5 брейкпоинтов. Хардкода цветов в компонентах нет.
- **GraphQL-схема.** 12 фрагментов, переиспользование через spread, разумная декомпозиция (`CoachRef` отдельно от `Coach`). Если бэкенд писать под этот контракт — он готов.
- **SEO-обвязка.** Уникальные `title`/`description`/`og:*`/`canonical` на каждый маршрут через `router.afterEach`, JSON-LD `SportsClub`, sitemap, robots, 6 OG-картинок. По полноте — выше среднего для SPA.
- **Состояния загрузки.** 10 из 11 страниц имеют loading/error/empty (`LoadingSkeleton`, `EmptyState`) — редкость для прототипа.
- **Типы.** `vue-tsc` строгий, 0 ошибок на 12 348 строк, `ReadonlyArray` в публичных сигнатурах, `RouteMeta` расширен через `declare module`.
- **Производительность.** 148 KB JS gzip, ручной `manualChunks` (vue / apollo), lazy-load страниц, `dist` 1.2 MB.
- **Доступность (частично).** 35 ARIA-атрибутов, `aria-expanded` на бургере, `aria-label` на всех иконочных кнопках, `:focus-visible` стили, ровно один `<h1>` на страницу.

## 9. План исправлений

### Приоритет 0 — до того, как показывать сайт кому-либо (1–2 часа)

1. Оживить «Записаться»: `to="/contacts"` на 9 кнопках (К-1).
