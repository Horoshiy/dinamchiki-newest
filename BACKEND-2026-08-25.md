## 2. Что сделано

### Бэкенд — новый проект `/home/clawd/dinamchiki-gql`

Node 22 · TypeScript · GraphQL Yoga · SQLite. **Живой: `https://apigql.dinamchiki.ru/query`**

- **Схема** (`src/schema.graphql`, 34 типа) — реализует контракт фронтенда целиком:
  Team, Coach, Tournament, Match, Player, GalleryAlbum, GalleryPhoto, Review,
  ContactInfo, Venue, PageContent + мутация `submitApplication`.
- **Контент** — `data/seed.json`, **генерируется из сущностей фронтенда**
  (`npm run seed`). Копировать данные руками означало бы гарантированный
  разъезд между сайтом и API.
- **Заявки** — SQLite (`data/leads.db`, WAL), переживают перезапуск.
  Есть серверная валидация: мутацию можно вызвать в обход формы.
- **CORS** — белый список источников.
- `GET /healthz` — статус, дата сида, число заявок.

### Инфраструктура

- systemd-юнит `dinamchiki-gql.service`: автозапуск, рестарт при падении,
  запись разрешена только в `data/`, `ProtectHome=read-only`, `NoNewPrivileges`.
- Caddy: `/etc/caddy/addons/apigql.conf` — проксирует `/query` и `/healthz`
  на `127.0.0.1:8175`, остальное 404, заголовки безопасности.
  Сертификат Let's Encrypt выпущен.
- Перед правкой сделан бэкап `/etc/caddy/Caddyfile`.

### Фронтенд (бета)

- `USE_MOCKS_ONLY = false` — сайт работает на реальных данных.
- При недоступности бэкенда автоматический откат на моки + флаг
  `window.__gqlFellBack`, по которому e2e отличает настоящие данные от
  запасных: визуально это неразличимо, а разница принципиальная.
- **Выкачен на бету** (`/srv/dynamost-flowise`), бэкап предыдущей сборки сделан.
- `robots.txt` на бете теперь `Disallow: /` — раньше бета была открыта
  для индексации.

### Тесты фронтенда переписаны под реальный путь данных

Раньше они гоняли mock-ветку. После включения бэкенда это стало проверкой
кода, которого в проде нет. Теперь тесты ходят через Apollo — как прод, —

с контрактом, валит тест.

проверялось «заявка НЕ помечается отправленной», теперь — «заявка реально
принимается». Гарантия честности осталась и усилилась: отдельный тест
проверяет, что **ошибка сервера не выдаётся за успешную отправку**.

### Контрактный тест — главный

`dinamchiki-gql/tests/schema.test.ts` вытаскивает все 21 операцию из

## 5. Найдено и исправлено по ходу

**1. CORS открывал API всему интернету.**
GraphQL Yoga трактует пустой список `origin` как «отразить любой Origin».
Посторонний сайт получал `access-control-allow-origin` со своим адресом и мог
дёргать мутацию заявок. Исправлено на явный отказ.

**2. `Origin: null` проходил как разрешённый.**
Первая версия отказа возвращала `null` — а это ровно то, что браузер шлёт из
sandboxed-iframe и `data:`-документов, то есть такой ответ им и разрешал
доступ. Заменено на `https://denied.invalid` (зона зарезервирована RFC 2606,
реальный сайт её иметь не может). Нашёл тест `Origin: null не получает
разрешения`.

**3. `addTypename: false` ломал нормализацию Apollo.**
В Apollo Client 3.14 опция не поддерживается: кеш возвращал пустые объекты.
Проявилось при переводе тестов на реальную схему.

**4. Два экземпляра `graphql` в тестах бэкенда.**
Схема из yoga несовместима с `graphql()` из пакета. Вместо обхода вынес
сборку приложения в `src/app.ts` — теперь тесты поднимают ровно ту же
обвязку, что работает в проде, включая CORS.

## 8. Подготовка к раскатке на прод через CI/CD

Бета-имена нигде не зашиты в коде — переход сводится к конфигурации.
После уточнения про бету доделано:

### Убраны ловушки

1. **`.env.production.example` указывал на бета-API.** Кто-то скопировал бы
   его для прода, и боевой сайт молча ходил бы в бета-бэкенд. Теперь там
   плейсхолдеры `<боевой-api>` / `<боевой-домен>`.
2. **`app.config.ts` имел бета-хост значением по умолчанию.** Забытая
   переменная в боевой сборке давала бы тот же эффект. Теперь дефолт —
   заведомо нерабочий адрес в зоне `.invalid`.

### Сборка прода с бета-настройками теперь падает

`vite-plugins/env-guard.ts`: при `VITE_ALLOW_INDEXING=true` проверяет
`VITE_GRAPHQL_HTTP`, `VITE_GRAPHQL_WS`, `VITE_SITE_URL`, `VITE_CLUB_PHONE`.
Валит сборку, если значение пустое, содержит незаполненный плейсхолдер
или указывает на бета-хост. Перечисляет все проблемы разом.

Проверено на трёх сценариях: шаблон с плейсхолдерами — падает; корректный
домен сайта, но API на бете — падает с указанием на бета-хост; полностью
заполненный прод — собирается и выпускает `robots.txt` с `Allow: /`.
Покрыто 11 тестами.

### Чеклист перехода

1. `.env.production` из `.env.production.example`, заполнить все значения.
2. Добавить боевой домен фронтенда в `CORS_ORIGINS` юнита `dinamchiki-gql`.
3. Vhost Caddy с боевыми именами по образцу `docker/Caddyfile.example`
   и `/etc/caddy/addons/apigql.conf`.
4. **Заменить `connect-src` в CSP** — там перечислен бета-API. Иначе браузер
   заблокирует запросы, и сайт молча останется без данных. В обоих
   конфигах (`docker/nginx.conf`, `docker/Caddyfile.example`) стоит
   предупреждение.
5. Убрать `X-Robots-Tag: noindex` — он нужен только бете.
6. Заменить демо-контакты в `src/shared/config/club.ts`, снять
   `IS_DEMO_CONTACTS`.
7. `npm run verify`, затем `BASE_URL=https://<боевой-домен> npm run e2e`.
