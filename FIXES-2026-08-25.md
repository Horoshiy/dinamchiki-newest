## 1. Критические (все закрыты)

### К-1. Кнопка «Записаться» не работала нигде — ИСПРАВЛЕНО

9 кнопок получили цель. Введён `SIGNUP_ROUTE = '/contacts#lead'` в `src/shared/config/club.ts`.

Попутно найдено и исправлено то, чего не было в отчёте: **`BaseButton` с `to` рендерил `<a>` вообще без `href`**. Причина — `:href="href"` со значением `undefined` попадал в fallthrough-атрибуты `RouterLink` и затирал вычисленный им href. Клик работал, но Ctrl+клик, «открыть в новой вкладке», фокус с клавиатуры и краулеры — нет. Атрибуты теперь собираются в объект `linkAttrs` и биндятся через `v-bind`. Проверено: 8 из 8 ссылок на главной имеют href.

Второй сопутствующий дефект: якоря `#lead` на `/contacts` не существовало, а `scrollBehavior` отрабатывал раньше рендера ленивой страницы. Добавлен `id="lead"` и ожидание элемента через `requestAnimationFrame` с отступом под липкую шапку. Проверено: `scrollY = 288` вместо 0.

### К-2. Формы имитировали отправку — ИСПРАВЛЕНО

`useSubmitApplicationMutation` больше не возвращает `{ ok: true, leadId: 'lead-…' }` при отсутствующем бэкенде. Введён флаг `notDelivered`, обе формы показывают состояние **«Онлайн-заявка пока не работает»** с прямыми контактами (новый компонент `DirectContacts.vue`: телефон, Telegram, WhatsApp, email).

`HomeCta` больше не имеет собственной поддельной логики (`submitted = true` + `setTimeout`) — ходит через тот же composable с валидацией. Проверено в браузере: ложного success нет.

Попутно исправлены битые ссылки в `HomeCta`: `tel:+749****4567` и `https://wa.me/749****4567` — с буквальными звёздочками.

### К-3. Этап 11 (GraphQL) — ЧАСТИЧНО, упирается в бэкенд

Развернуть `apigql.dinamchiki.ru` я не могу. Что сделано со стороны фронта:

- Схема расширена недостающими сущностями из ТЗ: **`PageContent` и `Review`** (их не было вовсе), плюс `gallery` в `CoachFields`.
- `USE_MOCKS_ONLY` теперь честно описан: пока `true`, приём заявок недоступен и UI об этом говорит.
- В `useGraphQLWithFallback` исправлена **реальная ошибка**: в mock-режиме `mockFn` вызывался один раз и не реагировал на смену переменных — переключение вкладок состава и переходы между детальными страницами не обновляли данные. Добавлен `watch` по переменным и защита от гонки ответов (устаревший ответ не затирает свежий).
- `useMutation` поднят в setup-контекст (С-7).

Переключение на бэкенд теперь действительно сводится к одному флагу.

### Токен Яндекс.Диска — ТРЕБУЕТСЯ ДЕЙСТВИЕ ВЛАДЕЛЬЦА

При поиске токена для загрузки отчёта обнаружено, что ситуация хуже, чем зафиксировано в исходной экспертизе:

1. OAuth-токен Яндекс.Диска был **захардкожен в `bestplayer-bot/journalist_style.py:43`**, и этот файл **отслеживается git и запушен** в `github.com/Horoshiy/dynamost-admin-bot` (локальный HEAD совпадает с `origin/main`). Репозиторий приватный — анонимный запрос к GitHub API даёт 404, — что снижает остроту, но токен всё равно лежит в истории на серверах GitHub.
2. В `.git/config` этого репозитория **remote URL содержит GitHub Personal Access Token открытым текстом** (`https://Horoshiy:ghp_…@github.com/…`).
3. `config.py` (в `.gitignore`) хранит тот же токен как значение по умолчанию: `os.environ.get("YANDEX_DISK_TOKEN", "y0__…")`.

**Что сделано:** секрет убран из отслеживаемого файла — `journalist_style.py` берёт токен из `config.py`. Значение в рантайме то же самое (проверено), поведение бота не менялось, коммит не делался.

**Что должен сделать владелец — код этого не исправит:**

- **Отозвать и перевыпустить токен Яндекс.Диска.** Он в истории приватного репозитория; правка файла не убирает его из уже сделанных коммитов. Токен даёт полный доступ к диску (2.2 ТБ).
- **Отозвать GitHub PAT** и переключить remote на SSH или git-credential-helper.
- Убрать значение по умолчанию из `config.py`. Это требует источника переменных для systemd-юнита `bestplayer-bot.service` (сейчас у него нет `EnvironmentFile`, а `.env` читает только `fnl_sync.py`) — правка на работающем сервисе, поэтому без отдельного согласия я её не делал.
